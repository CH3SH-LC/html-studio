## 实际执行

每份原稿先在独立 Edge 打开，再进入已打包的桌面 EXE。逐页检查标题的可见性、位置和配图加载并保存截图，双击修改真实标题，选择原有图片并换成本地 PNG，保存至另一个目录，重新打开副本，再从换图页播放、前后翻页、跳到末页、Esc 返回。最后将 Edge 设为离线，独立打开保存副本并核验改字、换图、其他图片和翻页。封装稿额外比较替换前后图片的布局尺寸。

三份论文稿有 ../assets 形式的上级素材引用，首次打开按“定位素材”选择原件的 paper-master 文件夹；这是实际流程中的额外一步。另存出的副本携带所需素材，之后重开无需再次定位。四份输入文件的 SHA-256 均未改变。

自动化使用真实 Electron 窗口和渲染引擎，打开/保存/选图对话框以返回文件路径的测试替身运行。网页键盘由 Playwright 输入；Esc 使用 Electron sendInputEvent 进入 before-input-event。独立 Edge 不连接个人浏览器配置。原生 Windows 补验另行记录，避免把这些证据混为一谈。

## 发现并修复

- 活动页 CSS：AI 稿通过 .slide.active .anim 才显示文字，旧版强制显示页容器仍留下透明子内容。现在将活动态规则映射到编辑页并把入场动画停在完成状态，正文与缩略图同时可见；源 class、CSS 和动画未改写。兼容 Chromium 对普通 CSSStyleRule 暴露空 cssRules 的行为，恢复隐藏页 Flex/Grid 显示方式。
- 封装 HTML：旧版只识别到 Unpacking 封面。现在直接解析 __bundler/template 与 manifest 的 JSON 和 gzip 素材，不在编辑器运行原稿加载脚本；识别六页 1920×1080 deck-stage 正文。保存仅替换原封装中的模板，原加载器和内嵌素材继续保留。
- 播放同步：优先复用原稿的分页按钮或 deck-stage API，同步动画、计数和当前页。等待异步解包及开放 shadow DOM 中的真实舞台，连续导航按动画帧串行应用，避免快速按键使两页同时 active。
- 组件换图尺寸：x-dc 将 CSS 解析为组件样式，不支持新增 !important 值，导致已换图片播放时变成固有尺寸。对这类封装采用它可接受的行内样式，保存重开、应用播放和独立浏览器均保持 46×46 的原布局尺寸。

测试工具也修正了两项假设：部分真实标题是 div 而非 h1；Playwright 的 CDP 按键不会触发 Electron 的 before-input-event，因此不能用它判断原生 Esc 是否正常。这两项没有算作产品缺陷。

## 0.3.1 开源发布补验

干净源码副本可以重新安装依赖、下载并校验全部 24 个原件、下载官方 Electron、构建并通过完整回归。首次 Windows 云端验收另发现一个小窗口问题：1920px 稿件适合窗口后，文字选框上下拖动区域重叠，拦截双击的第二次点击，导致标题未进入编辑。

该问题已在本机 960×640 窗口复现（点击命中上下拖动边框，文字不可编辑）。0.3.1 限制边框向对象内部占用的范围，保留中心文字点击区域；真实 Gemini 回归固定缩小到 960×640，并显式检查双击后文字获得编辑焦点。上述原生 Windows 补验属于 0.3.0；0.3.1 的小窗口覆盖属于桌面自动化。

最新自动验收结果见仓库 Actions；发布附件 acceptance-summary.json 提供对应源码提交和不含本机路径的验收摘要。详细原始报告及截图保留本地 test-results/，不随源码仓库分发。

## 已知边界

这四份稿件不是全体 AI 成稿的统计样本。仅有静态正文模板的这类封装已覆盖；任意 React/Vue 应用、纯脚本生成页面、iframe 拼页、嵌套 Reveal 纵向页、图表内部数据和 Canvas 对象编辑仍不保证。网络素材不会自动下载。本次独立离线验证使用这些稿件已有的本地/内嵌素材。

原生文字输入不等同于人工中文输入法组词；全新 Windows 安装环境、普通用户易用性及所有显示缩放组合仍未验收。应用未做商业代码签名。外部语料及论文图仅保存在研究/验收目录，不随应用便携包分发。
